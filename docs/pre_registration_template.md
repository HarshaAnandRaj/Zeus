# Pre-registration template (mandatory for every experiment)

Copy this file to `docs/<name>_protocol.md`, fill every section, commit
BEFORE any compute. An experiment without a committed protocol does not
exist and its results license nothing.

## Question

One sentence. No consciousness language in the contract.

## Frozen conditions

Code paths, checkpoints (exact steps + hashes), corpus files, seeds,
hyperparameters, run dirs. Anything not listed here must not change mid-run.

## Bars (all required unless stated)

Quantitative, with CIs and exact thresholds. Name the baseline each bar is
measured against. Pre-register the decision for borderline outcomes
("within noise band" -> undecided, never a pass).

## Non-claims

What this experiment cannot license even on a pass (legibility, state
authorship, memory, action, emergence, consciousness — delete only with
explicit justification).

## Pre-committed consequences

Pass -> ... . Fail -> ... . Name the next step for EACH outcome, including
"undecided." No experiment ends in "more research is needed" without a
specified, falsifiable follow-up or a retirement.

## Capability status and bounded authorization

Declare Class O, Class E, capability instrument, or not applicable. Class O
is observed degrees of freedom: evidence only, no continuation permission.
Class E is engineered prerequisites: name the single experiment earned at
registration and record when that authorization is consumed.

For a capability instrument, define the degrees-of-freedom metric, estimator,
sampling unit, support requirements, uncertainty, fixed controls, calibration
failure rule and causal assumptions. Distinguish observational geometry from
controllability and action entropy from empowerment. Name the one follow-up
experiment earned, freeze its full protocol and bars in this registration,
and record when used. No instrument authorizes a phase or passes a pillar.
An uncalibrated ruler needs a frozen baseline-relative contract before its
evaluation; no post-result relaxation. The 2026-09-06 saved-report pilot is
NOT READY; a proposed measurement component is not an active instrument.

Policy evaluations must freeze decoding and separately specify world and
policy-sampling seeds, repeats, and uncertainty. Retain paired worlds across
conditions. Sampled training evidence cannot replace a greedy endpoint, or
vice versa, after exposure.

## Emergence-grading checklist (mandatory at verdict, not at launch)

Every apparent positive must be graded before entering any evidence column.
Ask all six; record answers in the verdict entry:

1. **Designed setup?** Was the outcome reachable only inside machinery built
   to produce it (losses, incentives, forced choices)? If yes -> engineering
   result, not emergence.
2. **Unprogrammed setpoint?** Given the setup, was the specific outcome
   (value, timing, shape) specified in advance by anyone? Only unprogrammed
   setpoints count as emergent.
3. **Selection artifact?** Was the measured population pre-selected for the
   property (pinned dims, filtered samples, tuned thresholds)? If yes ->
   circular until replicated unselected.
4. **Theory-predicted anyway?** Does an existing model predict this outcome
   for ANY system with these forcings (not just ours)? If yes -> confirmation
   of the forcing, not discovery about the subject.
5. **Goal-adjacent or substrate-level?** Dynamics curiosities (tempo,
   geometry, necessity) do not transfer upward without a separate causal
   argument. State which pillar, if any, the result bears on — "interesting"
   is not a pillar.
6. **Survives the audit it was graded with?** Would this positive have passed
   the current rulers (calibrated baselines, relative bars, direct reading)?
   Re-grade old positives when rulers change; retire the ones that fail.

Verdict labels allowed: PASS / FAIL / UNDECIDED / VOID (broken instrument —
never a result). "Actually a win" is not a label.
